# Target Database Project and EF Migration Strategy

## Supported models

### Model A — SQL Project First

Use when:

- stored procedures/functions are important;
- database permissions are complex;
- deterministic deployment scripts are required;
- the service owns significant database-side logic.

Structure:

```text
CustomerDataService.Database/
├── CustomerDataService.Database.sqlproj
├── Schemas/
├── Tables/
├── Views/
├── StoredProcedures/
├── Functions/
├── Security/
├── PreDeployment/
└── PostDeployment/
```

### Model B — EF Core Migrations First

Use when:

- the service mostly owns tables, keys, indexes, and simple constraints;
- aggregate persistence is implemented with EF Core;
- little database-side programmability exists.

Structure:

```text
CustomerDataService.Migrations/
├── CustomerDbContextFactory.cs
├── Migrations/
├── DesignTime/
└── CustomerDataService.Migrations.csproj
```

### Model C — Hybrid

Recommended for many migrations.

Ownership rules:

- SQL project owns schemas, procedures, functions, security, and advanced indexes.
- EF migrations own selected service tables and ordinary relational changes.
- one manifest declares the owner of every object class;
- deployment order is explicit;
- no object is generated by both systems.

## Recommended deployment order

```text
1. SQL pre-deployment/foundation
2. EF migrations for service-owned tables
3. SQL project programmable objects
4. security grants
5. post-deployment validation
6. migration ledger entry
```

Or use SQL projects for all production DDL and EF migrations only to generate reviewed scripts.

## Database contract

Each service database must expose:

- schema version;
- contract version;
- supported procedures/API operations;
- compatibility policy;
- migration history;
- health query;
- permission baseline.

## CI checks

Fail the pipeline when:

- live drift exists;
- a SQL project and EF migration both own the same object;
- a destructive change lacks approval;
- a stored procedure references another domain database;
- runtime role receives DDL;
- deployment checksum differs from approved artifact.
